# 产品方案 v2 — 研发实施方案

> 对应产品方案：[产品方案-v2-客户端重构.md](./产品方案-v2-客户端重构.md)

## 技术选型

| 项 | 选择 | 原因 |
|---|---|---|
| 桌面框架 | Electron 35.x | 与现有 Node.js 后端天然融合 |
| 构建集成 | electron-vite 或 vite + electron-builder | 与现有 Vite 6 开发体验一致 |
| 打包 | electron-builder | Windows NSIS 安装包 |
| 窗口管理 | Electron BrowserWindow | 窗口模式 1200×800，F11 全屏切换 |

## 研发实施概览

```
第 0 步: Electron 壳搭建        (~3h)   不涉及业务代码，新增预览模式
第 1 步: 删除 RAG 知识库（前端） (~2.5h) 删文件、删状态、删 UI、改 SSE 函数签名
第 2 步: 合并个人信息+全局记忆   (~3h)   重写设置页 + 改后端 Profile API
第 3 步: 模型设置 UI 重设计     (~3h)   布局紧凑化
第 4 步: 对话界面微调           (~0.5h) 按钮布局调整
第 5 步: 助手 & 会话样式调整    (~2h)   Sidebar/Modal 优化 + 全屏/窗口双形态适配
第 6 步: 后端 RAG 代码逐步清理  (~2h)   按依赖链注释→测试→删除
第 7 步: 整体测试 & 打包        (~2h)   全功能回归 + Electron 打包
```

> 核心原则：每步做完 `npm run dev` 验证无 TS 编译错误 + 页面可正常渲染。前端先大刀阔斧删，后端逐步注释保守推进。

## 第 0 步：Electron 客户端搭建

### 目标
初始化 Electron 项目壳，保留现有 Vite React 开发环境，支持浏览器 dev 模式 + Electron 窗口模式。

### 操作步骤

#### 0.1 安装 Electron 依赖
```bash
npm install --save-dev electron electron-builder concurrently wait-on
npm install electron-is-dev
```

#### 0.2 创建主进程文件 `electron/main.ts`
- BrowserWindow 1200×800，minWidth 900, minHeight 600
- 注册全局快捷键 F11 切换全屏
- **在 React 顶部栏右侧增加全屏按钮**：通过 preload 暴露 `toggleFullscreen()` API，React 调用
- 开发模式加载 http://localhost:3000，生产模式加载 dist/index.html
- 窗口标题栏保留默认系统控件（最小化/最大化/关闭）
- **启动 Express 后端**：在主进程中 `import` 并启动 `server/src/index.ts`（端口 3001），确保生产模式下前端 API 请求可达

#### 0.3 创建预加载脚本 `electron/preload.ts`
- contextBridge 暴露 `toggleFullscreen()` API 供 React 调用
- 暴露 `isElectron` 标识，供前端 `api.ts` 判断是否切换 API base URL
- 当前阶段暴露全屏切换 + Electron 标识，后续按需扩展

#### 0.4 配置 Vite + Electron 联调
- 修改 `package.json` scripts：
  - `"dev"` → 仅启动 Vite（保留浏览器调试能力）
  - `"dev:electron"` → 启动 Vite + wait-on → 启动 Electron
  - `"build"` → Vite build + electron-builder
- 修改 `vite.config.ts`：生产模式 base 设为 `./`（Electron file:// 协议需要相对路径）

#### 0.5 适配浏览器/Electron 双环境 API base URL
**文件**: `src/services/api.ts`
- 浏览器 dev 模式：`BASE_URL = '/api'`（Vite proxy → localhost:3001）
- Electron 模式：`BASE_URL = 'http://localhost:3001/api'`（直连 Express）
- 通过检查 `window.electronAPI?.isElectron` 或类似方式判断环境

#### 0.6 全屏/窗口双形态预览模拟
由于开发阶段在浏览器中进行，需要模拟客户端两种窗口形态的 UI 效果。

**文件**: `src/App.tsx`（新增预览模式状态）
- 新增 State: `isWindowedPreview: boolean`，默认 `false`（即默认全屏模式，与现有行为一致）
- 在顶部栏或设置入口提供切换按钮：点击后在"全屏预览"和"窗口预览"之间切换

**窗口预览模式效果**:

## 第 6 步：后端 RAG 代码逐步清理

### 目标

### 依赖链梳理

**关键澄清：文档上传走两条独立路径**:
```
路径A（知识库上传 → 删除）:
  SettingsArea → knowledgeApi.uploadDocument → routes/knowledge
    → ProcessingQueue → KnowledgeService.processDocument
      → LoaderService.loadFile → chunkText → MultimodalEmbeddingService
  这条路径完全为 RAG 知识库服务，整体删除。

路径B（聊天文档上传 → 保留）:
  ChatArea → chatFileApi.upload → routes/chat POST /upload-file
    → LoaderService.loadFile → DeepSeekOcrService（扫描件）
  这条路径直接使用 LoaderService，不经过 KnowledgeService。
  删除 KnowledgeService 不影响聊天中的文档上传。
```

```
保留（被其他模块依赖）：
  ├── EmbeddingService          ← MemoryService 向量化需要
  ├── RerankerService           ← MemoryRetrievalService 精排需要
  ├── LoaderService             ← chatFileApi 文档上传使用（路径B）
  ├── DeepSeekOcrService        ← 扫描件 OCR
  ├── chunk.ts / cleanText.ts   ← 底层工具（MemoryService可能间接引用）
  └── MultimodalEmbeddingService ← 暂无外部引用，保留以备后续

注释/删除（仅被知识库管理使用）：
  ├── routes/knowledge.ts       ← 所有 KB CRUD 端点
  ├── KnowledgeService          ← search() 仅被 chat.ts 引用，processDocument() 仅被 ProcessingQueue 引用
  ├── ProcessingQueue           ← 仅被 KnowledgeService.processDocument 使用
  └── rewriteQuery.ts           ← 仅被 KnowledgeService.search() 使用
```
