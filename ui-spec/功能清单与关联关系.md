# AI Chat 应用 — 功能清单与模块关联关系

---

## 一、整体架构层级

```
App.tsx (状态中心)
├── Sidebar.tsx (导航)
│   ├── 助手列表 + 话题列表
│   └── 设置模式 → 切换下方内容区
├── ChatArea.tsx (对话主界面) ←→ 与 SettingsArea.tsx 互斥显示
├── SettingsArea.tsx (系统设置) ←→ 与 ChatArea.tsx 互斥显示
├── AssistantModal.tsx (助手编辑弹窗，全局层)
└── 各种子弹窗 (AddProviderModal, AddModelModal, FetchModelsModal, MemorySettingsModal, ProfileEditModal, 确认删除弹窗等)
```

**核心切换逻辑**：
- Sidebar 处于正常模式 → 右侧显示 ChatArea
- Sidebar 点击底部"设置"按钮 → 右侧切换为 SettingsArea，Sidebar 变为设置导航
- Sidebar 点击"退出设置" → 恢复 ChatArea

## 二、模块功能清单

### 2.1 App.tsx — 应用主控

**职责**：全局状态管理中心，不渲染可见 UI，只做数据调度和 props 分发。

| 功能 | 说明 |
|------|------|
| 初始化加载 | 启动时自动加载助手列表、供应商列表、模型列表 |
| 默认选中 | 自动选中第一个助手，加载其对话列表和最新对话 |
| 消息缓存 | 切换会话时保留上一个会话的流式状态（不中止后台 SSE） |
| 消息规范化 | 将数据库消息转为 UI 所需格式（解析 toolCalls/think 标签等） |
| 导航事件 | 记忆来源弹窗可通过自定义事件跳转到原始对话 |

**持有的全局状态**：
- `assistants[]` — 所有助手
- `providers[]` — 所有供应商
- `models[]` — 所有模型
- `conversations[]` — 当前助手下所有对话
- `currentConversationId` — 当前选中的对话 ID
- `messages[]` — 当前对话的消息列表
- `conversationStates` — 每个对话的 UI 状态（深度思考开关、联网搜索开关、流式内容缓存）
- `settingsTab` — 当前是否在设置模式 (`null` | `'model'` | `'memory'` | `'profile'`)

### 2.2 Sidebar.tsx — 侧边导航

**两种模式**：正常模式（助手/话题切换）+ 设置模式（设置标签导航）

#### 正常模式

| 区域 | 功能点 | 说明 |
|------|--------|------|
| 顶部 Tab | 助手 / 话题 | 两个标签切换下方列表 |
| 助手列表 | 显示所有助手 | emoji + 名称，点击切换到该助手 |
| 助手列表 | 三点菜单 | 悬停显示，可编辑/删除助手 |
| 助手列表 | 删除确认 | 自定义弹窗，显示助手名，二次确认 |
| 话题列表 | 显示当前助手的对话 | 按 updated_at 降序，点击切换对话 |
| 话题列表 | 悬停删除 | 首次点击变红"再次点击确认删除" |
| 底部 | 新建助手 / 新建话题 | "+" 按钮触发 |
| 底部 | 设置入口 | 齿轮图标，点击进入设置模式 |

#### 设置模式

| 区域 | 功能点 | 说明 |
|------|--------|------|
| 标签页 | 模型设置 | Settings 图标 |
| 标签页 | 全局记忆 | Brain 图标 |
| 标签页 | 个人信息 | User 图标 |
| 底部 | 退出设置 | 返回正常模式 |

**关联关系**：
- 切换助手 → App 重新加载该助手的对话列表 + 消息
- 切换对话 → App 加载该对话的消息（含流式缓存恢复）
- 新建助手 → 弹出 AssistantModal，保存后刷新 Sidebar 列表
- 删除助手 → 同时删除其下所有对话和消息，刷新列表
- 进入设置 → Sidebar 变为设置导航，右侧由 ChatArea 切换为 SettingsArea

### 2.3 ChatArea.tsx — 对话主界面

#### 消息区域

| 元素 | 说明 |
|------|------|
| 系统提示词卡片 | 可点击编辑，最多 3 行，无提示词时显示占位提示 |
| 用户消息气泡 | 右侧绿色圆角，显示"用户"标签 + 纯文本 |

| 思考过程折叠 | ThinkBlock 组件，灰色文字，可折叠/展开 |
| 工具调用卡片 | ToolCallBlock，显示工具名/参数/结果，支持嵌套层级 |
| 推理交错渲染 | 思考文本与工具调用按 `reasoningSegments` 顺序交替展示 |
| 中止状态 | 黄色警告图标 + 中止提示文字 |
| 流式动画 | 三个跳跃圆点 |

#### 消息底部操作栏（非流式时显示）

| 按钮 | 说明 |
|------|------|
| 时间戳 | `YYYY-MM-DD HH:mm:ss` 格式 |
| 重新生成 | 回转图标，仅最新 AI 消息可用 |
| 复制 | 点击变对勾，2 秒恢复 |
| Token 用量 | 悬停显示 TTFT、tokens/秒、prompt/completion 详情 |

#### 输入区域

| 元素 | 说明 |
|------|------|
| 文件预览区 | 缩略图/图标 + 文件名 + 删除按钮 |
| 文本输入框 | Enter 发送，Shift+Enter 换行 |
| 深度思考按钮 | 仅推理模型可见，切换开关 |
| 联网搜索按钮 | 切换开关 |
| 上下文轮数指示器 | 显示 `上下文 N/M 轮`，达上限高亮 |
| 文件上传按钮 | 纸夹图标，支持多选 |
| 发送按钮 | 文本或文件不为空时可点击 |
| 停止生成按钮 | 红色方形，仅流式时显示 |
| 底部提示 | "内容由 AI 生成，请谨慎甄别" |

#### Header 栏

| 元素 | 说明 |
|------|------|
| 助手名称按钮 | emoji + 名称，点击编辑助手 |
| 隐私模式开关 | 盾牌图标，红色=隐私中（不提取记忆）/ 灰色=正常 |

**关联关系**：
- 发送消息 → `chatSSE()` → 服务器 `/api/chat/completions` → SSE 流式返回 → 逐 token 渲染
- 重新生成 → `regenerateSSE()` → 服务器 `/api/chat/regenerate` → 删除旧消息 → 重新生成
- 停止生成 → `AbortController.abort()` → 服务器端中断 → `done(aborted: true)`
- 深度思考/联网搜索 → 作为请求参数传给服务器 → 影响 LLM system prompt 和工具可用性
- 文件上传 → `/api/chat/upload-file` → 返回提取文本 → 拼接进用户消息
- 隐私模式 → 更新 conversation.privacy_mode → 记忆提取时跳过该对话
- Header 助手名点击 → 弹出 AssistantModal 编辑当前助手
- 切换对话 → App 缓存当前流式状态，加载新对话消息

## 三、服务器端功能与前端关联

### 3.1 聊天 API — `POST /api/chat/completions`

**前端调用**：`chatSSE()` in [src/services/api.ts](src/services/api.ts)

| 功能 | 前端触发 | 服务器处理 |
|------|----------|------------|
| 流式对话 | ChatArea 发送 | SSE 流式返回 token/reasoning/tool_call/done |
| 深度思考 | DeepThinkingButton | system prompt 注入 think 指令 |
| 联网搜索 | WebSearchToggleButton | `web_search` tool + `web_fetch` tool |
| 记忆检索 | 记忆启用时自动 | `search_memory` → `recall_context` → `recall_sources` |
| 文件解析 | 上传文件 | LoaderService 提取文本 / OCR |
| 上下文截断 | context_rounds 配置 | 轮数 × 2 条消息截断 + Chunk 归档 |
| 个人信息注入 | 自动 | UserProfileService 拼接到 system prompt |
| 性能指标 | 每次请求 | TTFT、tokens/秒、prompt/completion 用量 |

### 3.2 重新生成 API — `POST /api/chat/regenerate`

**前端调用**：`regenerateSSE()` in [src/services/api.ts](src/services/api.ts)

| 功能 | 说明 |
|------|------|
| 消息回滚 | 删除原 AI 回复，找到最后一条用户消息重新生成 |
| 错误回滚 | 生成失败时恢复被删除的原始消息 |

### 3.3 记忆系统

| 功能 | API | 触发方式 |
|------|-----|----------|
| 自动提取 | 无直接 API | 会话空闲 N 分钟后 ConversationIdleDetector 触发 |
| 向量搜索 | `POST /api/memory/search` | 聊天时 `search_memory` tool 自动调用 |
| 记忆 CRUD | `GET/PUT/DELETE /api/memory/*` | SettingsArea 全局记忆 Tab 手动操作 |
| 来源追溯 | `GET /api/memory/:id/sources` | 来源追溯弹窗 |

**记忆生命周期**：
```
对话 → 空闲超时 → LLM 提取候选记忆 → 去重(hash) → 嵌入向量 → 入库
                                                        ↓
聊天 → search_memory tool → 向量相似度搜索 → RerankerService 精排 → recall_context 召回完整内容
```

## 五、关键交互链路

### 发送一条消息的完整链路

```
用户输入文字 → 点击发送
  → ChatArea.handleSubmit()
    → api.chatSSE(assistantId, message, conversationId, thinkingMode, callbacks, files, options)
      → POST /api/chat/completions
        → 服务器：构建 system prompt（助手提示词 + 日期 + 个人信息 + 思考指令）
        → 服务器：加载历史消息（按 context_rounds 截断）
        → 服务器：调用 LLM（带 tool 定义：search_memory, web_search 等）
        → SSE 流式返回：
          meta → (reasoning → tool_call → tool_result) × N → token × N → done
      → ChatArea 实时渲染：
        reasoningSegments 按顺序交替展示思考块和工具调用卡片
        token 流式 Markdown 渲染
  → 对话完成后：ConversationIdleDetector 开始计时
    → 空闲超时 → 自动提取记忆 → 写入 memory 表
```

### 设置模型配置的影响链

```
SettingsArea 修改供应商/模型
  → api.providersApi.update() / api.modelsApi.create()
    → 数据库更新
      → App 刷新 providers/models 列表
        → AssistantModal 模型选择器同步
        → ChatArea 聊天使用的 LLM 自动切换
```

### 记忆检索链

```
用户发送消息（memory_enabled = true）
  → 服务器 system prompt 注入 search_memory tool 定义
  → LLM 判断需要记忆 → 调用 search_memory tool
    → 服务器：用户消息向量化 → 向量相似度搜索
      → RerankerService 精排 → 返回 top-K 记忆
        → LLM 可继续调用 recall_context（获取完整内容）→ recall_sources（获取来源）
```
